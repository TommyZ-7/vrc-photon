自動動作とキュー表示を3機能で統一する

自動圧縮・Discord 自動送信・AI 自動タグ付けの自動動作を3分割セグメントに、 一括処理を対象範囲2チップ＋実行ボタンに統一する。 キューは待機・実行待ち・実行中だけを同じ構成で表示し、履歴は持たない。 機能ごとの一時停止と、待機行の削除を追加する。

対象連携・自動 / ダッシュボード / 通知
自動動作しない / 即時 / 待機
キュー待機 / 実行待ち / 実行中
履歴・失敗履歴なし / 失敗は通知
表示順ヘッダー → 機能固有 → 自動動作 → 一括処理 → キュー
Q1 / Q9

一括処理は手動のみ

既存分を自動で積まない。対象範囲は「一括処理」ボタンが対象にする写真の範囲を決める。

手動のみ
Q2

「新規」はライブラリ追加基準

有効化後に索引された写真を新規とする。Discord の撮影時刻カットオフは廃止。

photos.created_at
Q4 / Q10

マスタースイッチは残す

自動動作が「しない」でも一括処理は使える。無効になるのは機能のマスタースイッチがオフのときだけ。

Off でも一括処理は有効
Q5 / Q13

自動動作も一括処理もセグメント

「自動動作」は3分割、「一括処理」の対象範囲は2分割のセグメント。カード化せず、見出し・選択・実行ボタンだけを置く。

カード化しない
Q14 / Q15

一時停止は設定に保存

再起動後も停止を維持する。停止中は新しいジョブを取得しないだけで、実行中は完了し、自動投入は続く。

開始だけ止める
Q16 / Q19

キューは処理中だけ、失敗は通知

待機・実行待ち・実行中だけを表示する。失敗・完了・履歴は出さず、失敗は通知モーダルで最新5件と再試行を出す。

履歴なし
Q17

ダッシュボードは混合キュー

3機能を混ぜた一覧に置き換える。一時停止／再開はダッシュボードには置かず、各機能詳細で操作する。

表示専用
Q18

待機だけ削除できる

行単位と一括削除を用意する。実行待ち・実行中は削除しない。一括削除の確認は件数だけを出す。

待機のみ

7. 判断と挙動の確認

実装前に合意する範囲
項目決定補足
自動動作しない / 即時 / 待機3機能で同じ `AutoMode`。3分割のセグメントで選ぶ。
マスタースイッチ機能ごとに残す自動圧縮は `auto_compress_enabled`、Discord は `discord_enabled`、AI は `ai_tagging_enabled`。
一括処理対象範囲2分割セグメント ＋ 実行ボタン「対象範囲」ではなく「一括処理」と表示し、自動動作と同じセグメントデザインにする。
「しない」の一括処理有効マスタースイッチがオンの間は使える。無効になるのはマスタースイッチがオフのときだけ。
表記ヒント・重複ラベル・空表示なし#627 / #629 の「連携・自動タブの余計な表記削除」に合わせる。
表示順ヘッダー → 機能固有 → 自動動作 → 一括処理 → キュー3カードで同じ順にする。
セットアップ自動動作だけ対象範囲・一括処理は表示しない。圧縮と Discord のマスタースイッチは残す。
AI の設定導線削除AI カードの「設定を開く」ボタンと案内文を置かない。
AI 即時準備完了時のみ積む未準備では積まない。待機は未準備でも waiting で積む。
Discord の対象未送信の全写真送信成功なし・アクティブ送信なし・削除中でない。失敗・取消は含む。
キューの内容待機・実行待ち・実行中だけ失敗・完了・履歴は表示しない。失敗は通知へ。
ダッシュボード3機能の混合キュー圧縮専用パネルを置き換える。一時停止／再開は置かない。
一時停止設定に保存 / 再起動後も維持停止中は新規取得を止める。実行中は完了し、自動投入は続く。

8. 移行と挙動変化

リリースノートに明記する
旧設定新設定利用者に見える変化
`auto_compress`（bool）`auto_compress_enabled`機能のマスタースイッチ。false はスイッチオフとして移行する。
`auto_compress_immediate``auto_compress.mode`true→即時 / false→待機。マスタースイッチがオフなら自動動作は動かない。
`auto_compress_backlog``auto_compress.scope`true→既存も含める / false→新規のみ。初回スキャンでは自動投入しない。
`discord_auto_mode``discord_auto.mode`そのまま。`discord_auto_since` は `activated_at` に移り、自動投入の撮影時刻判定には使わない。
`ai_tagging_auto` (bool)`ai_tagging_auto.mode`true→即時 / false→しない。待機が新設され、未準備でも waiting で積める。
—`auto_compress_queue_paused` / `discord_queue_paused` / `ai_tagging_queue_paused`新規。既定 false。再起動後も停止状態を維持する。
Discord 送信履歴なし履歴カードと「履歴を消去」を削除する。terminal 行は通知とテスト送信の結果解決にだけ使う。
レビュー時の確認ポイント
  • マスタースイッチがオンのまま自動動作を「しない」にしても、一括処理が使えるか。
  • 自動動作が3分割セグメント、一括処理の対象範囲が2分割セグメントになっているか。
  • 3カードの表示順が「ヘッダー → 機能固有 → 自動動作 → 一括処理 → キュー」で揃っているか。
  • 自動動作と一括処理がカード化されず、見出し・セグメント・実行ボタンだけになっているか。
  • 確認ダイアログが件数だけになっているか。余計な注意書きがないか。
  • ヒント行・重複ラベル・空表示が残っていないか。
  • AI カードから「設定を開く」ボタンと案内文が消えているか。
  • セットアップ3ページに一括処理がなく、自動動作だけがあるか。
  • ダッシュボードが3機能の混合キューになり、機能バッジと待機行の削除があるか。
  • 機能詳細のキューに一時停止／再開、待機をすべて開始／削除、待機行の削除があるか。
  • キューに失敗・完了・履歴が出ず、失敗が通知モーダルに最新5件で出るか。
  • Discord の送信履歴カードと「履歴を消去」が消えているか。
  • 旧設定の移行と、`discord_auto_since` 廃止の挙動変化に納得できるか。
