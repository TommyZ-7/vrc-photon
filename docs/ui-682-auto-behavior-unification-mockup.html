#682settings unification

自動動作の設定を3機能で統一する

自動圧縮・Discord 自動送信・AI 自動タグ付けの自動動作を3分割セグメントに、 一括処理を対象範囲2チップ＋実行ボタンに統一する。 一括処理は自動動作が「しない」でも使え、機能のマスタースイッチがオフのときだけ無効になる。

4. Discord の一括送信確認

対象件数と非公開インスタンスの注意

「未送信を一括送信」を押したときだけ出す。0件ならダイアログを出さず、 「送信対象の未送信写真はありません。」をトーストで出す。OK で既存の同意が 未記録なら記録し、pending で積む。自動動作が「しない」でも実行できる。

未送信写真の一括送信

既存の未送信写真 128 件 を Discord へ送信します。 Webhook の投稿先を確認してください。
非公開インスタンスで撮影した写真も含まれます。

5. 判断と挙動の確認

実装前に合意する範囲
項目決定補足
自動動作しない / 即時 / 待機3機能で同じ `AutoMode`。3分割のセグメントで選ぶ。
マスタースイッチ機能ごとに残す自動圧縮は `auto_compress_enabled`、Discord は `discord_enabled`、AI は `ai_tagging_enabled`。
一括処理対象範囲 ＋ 実行ボタン「対象範囲」ではなく「一括処理」と表示し、ボタンと同じブロックに置く。
「しない」の一括処理有効マスタースイッチがオンの間は使える。無効になるのはマスタースイッチがオフのときだけ。
表示順ヘッダー → 機能固有 → 自動動作 → 一括処理 → 状態3カードで同じ順にする。
セットアップ自動動作だけ対象範囲・一括処理は表示しない。圧縮と Discord のマスタースイッチは残す。
AI の設定導線削除AI カードの「設定を開く」ボタンと案内文を置かない。
AI 即時準備完了時のみ積む未準備では積まない。待機は未準備でも waiting で積む。
Discord の対象未送信の全写真送信成功なし・アクティブ送信なし・削除中でない。失敗・取消は含む。

6. 移行と挙動変化

リリースノートに明記する
旧設定新設定利用者に見える変化
`auto_compress`（bool）`auto_compress_enabled`機能のマスタースイッチ。false はスイッチオフとして移行する。
`auto_compress_immediate``auto_compress.mode`true→即時 / false→待機。マスタースイッチがオフなら自動動作は動かない。
`auto_compress_backlog``auto_compress.scope`true→既存も含める / false→新規のみ。初回スキャンでは自動投入しない。
`discord_auto_mode``discord_auto.mode`そのまま。`discord_auto_since` は `activated_at` に移り、自動投入の撮影時刻判定には使わない。
`ai_tagging_auto` (bool)`ai_tagging_auto.mode`true→即時 / false→しない。待機が新設され、未準備でも waiting で積める。
レビュー時の確認ポイント
  • マスタースイッチがオンのまま自動動作を「しない」にしても、一括処理が使えるか。
  • 自動動作が3分割セグメントになっているか。対象範囲チップと見た目が分かれているか。
  • 3カードの表示順が「ヘッダー → 機能固有 → 自動動作 → 一括処理 → 状態」で揃っているか。
  • 「一括処理」ブロックに対象範囲と実行ボタンがまとまり、対象が分かりやすいか。
  • AI カードから「設定を開く」ボタンと案内文が消えているか。
  • セットアップ3ページに一括処理がなく、自動動作だけがあるか。
  • 旧設定の移行と、`discord_auto_since` 廃止の挙動変化に納得できるか。
