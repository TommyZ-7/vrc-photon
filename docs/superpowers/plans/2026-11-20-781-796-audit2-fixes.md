## Review Focus

- **Empty, tiny, or fully-missing libraries:** `Db::optimize()` runs `ANALYZE` on an empty table, and the index-plan test must still pass on a database seeded with a few thousand rows. An empty library must not panic or log an error; covered by Task 5.
- **Corrupt or oversized input at the DB boundary:** a caller can send thousands of AI tag keys, and a 500k-row library must not be materialized for a 5-photo random sample. Both must degrade predictably (truncate, bounded memory) instead of failing at SQLite's parameter cap; covered by Tasks 3 and 4.
- **Silent data divergence:** a failed `clear_display_derivative`, `restore_present`, or plugin-probe reset leaves the DB disagreeing with the filesystem. Every remaining data-change path must log the failure with the photo/plugin id, never `let _ =`; covered by Tasks 7 and 14.
- **Locale changes:** the cached card strings (badge, world, meta) key on language; switching language must not leave a stale badge. Covered by Task 10.
- **Settings persistence through the new nesting:** after `AppSettings` moves under `SettingsState.current`, every save path must still write the live settings and every restore path must still roll back. A missed `self.settings` → `self.settings.current` rename silently persists defaults; covered by Tasks 20 and 21.

Replace the whole `photo_ids_text` + `random_photos_text` block with a bounded selection. The exact algorithm, because the signature and test do not determine it:

```rust
pub fn random_photos_text(
    &self,
    filter: &PhotoTextFilter,
    limit: i64,
    seed: u64,
) -> Result<RandomPhotoSample> {
    let total = self.count_photos_text(filter)?;
    let take = usize_from_i64(clamp_limit(limit));
    let (where_sql, values) = build_text_filter(filter);
    let sql = format!("SELECT p.id{PHOTO_FROM} WHERE {where_sql}");
    let mut stmt = self.conn.prepare_cached(&sql)?;
    let mut rows = stmt.query_map(params_from_iter(values), |row| row.get::<_, i64>(0))?;
    // Keep the `take` smallest keys in a max-heap so memory stays O(limit)
    // while the output keeps the same order a full sort produced.
    let mut best: std::collections::BinaryHeap<(u64, i64)> = std::collections::BinaryHeap::with_capacity(take + 1);
    while let Some(row) = rows.next() {
        let id = row?;
        let key = (splitmix64(seed ^ id.cast_unsigned()), id);
        if best.len() < take {
            best.push(key);
        } else if best.peek().is_some_and(|worst| key < *worst) {
            best.pop();
            best.push(key);
        }
    }
    let mut keyed = best.into_vec();
    keyed.sort_unstable();
    let ids: Vec<i64> = keyed.into_iter().map(|(_, id)| id).collect();
    let photos = self.photos_by_ids(&ids)?;
    Ok(RandomPhotoSample { photos, total })
}
```

/// Refreshes SQLite's planner statistics so index choices match the data.

/// Must run on a writable connection: `ANALYZE` creates `sqlite_stat1`.

## Risks and mitigations

- **Planner statistics cost:** `ANALYZE` takes ~0.14 s at 200k rows. It runs at three coarse points only (first scan, `--once`, shutdown), never per loop iteration. If that ever becomes visible, gate the startup call on `initial_scan`.
- **`#[non_exhaustive]` is a breaking change** for downstream crates: every exhaustive match must gain a wildcard arm. Task 2 compiles all four crates; the daemon already has one.
- **AI tag truncation changes filter semantics** for callers that send more than 500 keys. The daemon never sends more (the MCP client sends user tags), and the cap matches `BULK_TAG_CHUNK`, so the failure mode is now "fewer matches" instead of "request fails".
- **Heap sampling correctness:** the output must stay identical to the old full sort. Task 4's reference test compares exact ids and order over 1,000 photos; do not "improve" the tie-break.
- **`demo_build` split:** moving ~500 lines can silently change `cfg` semantics. Task 11 asserts identical test counts with and without the feature and builds both configurations.
- **Mechanical renames in #782:** a missed `self.settings` → `self.settings.current` compiles only when the field name does not exist on `SettingsState`, which is why the `save_scheduled` / `save_pending` / `scroll` / `integrations_*` exceptions are listed explicitly in Task 20. Re-read each whole-struct argument line.
- **Module splits and merge conflicts:** Tasks 15 and 16 are pure moves (`git mv` + item moves). Do not reformat while moving; that keeps the diff reviewable and the conflicts local.
- **#786 remains open:** thumbnail secondary-map growth is intentionally not addressed here. Note it in PR ②'s body as a known follow-up.
