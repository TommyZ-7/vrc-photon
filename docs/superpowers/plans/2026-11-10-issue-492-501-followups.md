# セッション表示フォローアップ (#492–#501) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Photos 画面のセッション表示に残っている 10 件の不具合・改善 (#492–#501) を、状態保持、スクロール、見出しレイアウト、レール／状態表示、分断セッション表示の 5 つの根因に分けて修正する。

**Architecture:** 既存の `SessionRows` / `PhotoBrowser` / `App` の構造を維持し、索引とは独立した改訂番号（AI 用・セッション用）と、見出し位置を保つスクロールアンカーを追加する。UI はセッションモードの行モデルとヘッダー描画だけを変更し、時系列モードと検索結果の既存挙動は変えない。

**Tech Stack:** Rust 2024, rusqlite, gpui-kit 0.8, SQLite

**Spec:** `docs/superpowers/specs/2026-11-09-session-groups-design.md` と Issue #492–#501 の本文。設計判断の更新は Phase 0 の docs PR で行う。

**Mocks:** `docs/ui-492-495-499-mockup.html`（#495 / #499 の承認用。Phase 0 で提示）

**Status:** 計画・モック承認済み（2026-11-10、Plannotator）。docs PR 作成中。実装未着手。

## Global Constraints

- 新しいテーブル・カラム・収集処理は追加しない。追加するのは `app_settings` の改訂番号キーだけ。
- daemon / IPC のプロトコル・メッセージ形は変更しない。UI は同一プロセスの `Db` を直接読む。
- 折りたたみ状態は永続化しない。アプリ起動中は保持し、再起動でリセットする。
- 索引再読込時は、新しい索引に存在するセッションの折りたたみ状態だけを引き継ぎ、消えたセッションの分だけ掃除する。
- 並びは全体・セッション内とも新しい順（`PhotoSort::Newest`）。
- 対象は可視写真（`p.status IN ('present', 'replaced')`）のみ。
- セッション表示は Photos 画面のみ。検索結果画面は時系列のまま。
- 新規・変更する UI 文言は `crates/i18n/locales/ja.yml` と `en.yml` の両方に追加する。
- `tr_args!` を新しく使うキーは `crates/i18n/tests/placeholders.rs` の `CALL_SITES` に追加する。
- UI の変更は、承認済みモックの範囲を超えない。#495 と #499 は Phase 0 のモック承認後に実装する。
- PR は根因ごとに分ける。1 PR に複数の根因を混ぜない。実装順は状態保持 → スクロール → 見出しレイアウト → レール／状態表示 → #499。
- 各 PR は最新の `main` から `git worktree` で切り、CI green を確認してから merge する。
- 検証: `cargo fmt --all -- --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace`
- 計画ファイルのチェックボックスは、その作業の完了時に `- [x]` に更新する。

## Review Focus

1. **AI タグ完了で索引を作り直さない**: AI 結果の保存が `library_revision` を動かすと、折りたたみ・スクロール・要約キャッシュがすべてリセットされる。`ai_revision` の軽量パスで、索引・行モデル・折りたたみを保持する。Task 1.1 / 1.2 / 1.3 で固定する。
2. **消えたセッションだけを掃除する**: 写真の追加・削除・スキャンで索引が変わっても、残存セッションの折りたたみを維持する。索引に現れない ID だけを落とす。Task 1.3 で固定する。
3. **見出しクリックで見出しが動かない**: クリックした見出しのビューポート相対 Y を保持し、下の写真行だけを伸縮する。手動スクロールが入ったら保留アンカーを破棄する。Task 2.2 / 2.3 で固定する。
4. **アニメーション中の月・年レール**: 確定後の `origins` ではなく、そのフレームの `heights_with_collapse` から作った origins を使う。終了時に位置が跳ばない。Task 2.1 / 2.3 で固定する。
5. **折りたたみセッションへの年レールジャンプ**: 対象写真が折りたたみ中なら展開してからオフセットを計算し、`max_offset` でクランプする。Task 4.2 で固定する。
6. **セッション終了のライブ更新**: `close_session` / プレイヤー退出が `session_revision` を進め、3 秒のライブ更新で可視見出しの要約だけを再取得する。写真索引は再読込しない。Task 4.1 で固定する。
7. **右ガターと月ピル**: 見出しカードの面を右ガターの手前で終わらせ、月ピル表示中も格納ボタン・滞在中バッジに重ならない。Task 3.1 / 3.2 / 3.3 で固定する。
8. **分断セッション**: 2 区間目以降の写真がどのセッションか分かり、年レールのジャンプが継続表示に着地する。折りたたみ時は最初の見出しだけを残す。Task 5.1 / 5.2 で固定する。
9. **カード全体クリックとボタンの二重発火**: 見出しカード全体のクリックで折りたたみ、右端のボタンは残す。ボタン側の `stop_propagation()` で二重発火せず、カード上から始まるドラッグスクロールでも誤作動しない。Task 3.3 / 3.4 で固定する。

```rust
fn revision(&self, key: &str) -> Result<i64> {
    Ok(self
        .get_setting(key)?
        .and_then(|value| value.parse().ok())
        .unwrap_or(0))
}

fn bump_revision(&self, key: &str) -> Result<i64> {
    let revision = self.conn.query_row(
        "INSERT INTO app_settings(key, value) VALUES (?1, '1') \
         ON CONFLICT(key) DO UPDATE SET \
            value = CAST(CAST(app_settings.value AS INTEGER) + 1 AS TEXT) \
         RETURNING CAST(value AS INTEGER)",
        params![key],
        |row| row.get(0),
    )?;
    Ok(revision)
}

pub fn ai_revision(&self) -> Result<i64> { self.revision("ai_revision") }
pub fn bump_ai_revision(&self) -> Result<i64> { self.bump_revision("ai_revision") }
```

    let mut origins = Vec::with_capacity(heights.len());

    for height in heights {
        origins.push(offset);
        offset += *height;
    }
    origins
}

pub(crate) fn top_photo_index_with_heights(
    &self,
    scroll_top: f32,
    heights: &[f32],

    if self.rows.is_empty() {

    (photo < self.photo_count).then_some(photo)
}
