# ヘッダーバッジの削除 (#666 / #667) 設計

> 状態: 実装完了（2026-11-16）
> モック: `docs/ui-666-667-header-badges-mockup.html`
> 対象 Issue: #666, #667

## 目的

ダッシュボードの圧縮キューと「連携・自動」の送信履歴で、ヘッダーに並ぶ件数・方針バッジを
削除し、タイトルと一括操作だけのヘッダーにする。件数はダッシュボードの統計カード、
サイドバーの圧縮バッジ、各行の状態バッジで確認できるため、ヘッダーのバッジを失っても
操作に必要な情報は残る。

## 現状

- 圧縮キューのヘッダーは `crates/ui/src/ui/compression.rs::queue_panel`（985〜1111 行）が描く。
  タイトルの右に「未完了 N」「未実行 N」「自動: 元画像を保持 / 置換」「失敗 N」の 4 バッジを出し、
  伸縮スペーサーの右に「待機をすべて圧縮」「失敗をすべて再試行」を置いている。
  件数は `App::active_job_count` / `waiting_job_count` / `failed_job_count`、
  再試行の可否は `retryable_failed_count` を使う。
- 送信履歴のヘッダーは `crates/ui/src/ui/discord.rs::send_history_card`（295〜369 行）が描く。
  タイトル、「待機 N」バッジ、「待機をすべて送信」（待機 0 件なら無効）、「履歴を消去」を並べる。
  待機件数は `App::send_waiting_count`。
- 圧縮キューのバッジ文言は `crates/i18n/locales/ja.yml` / `en.yml` の
  `compression.queue.active` / `.waiting` / `.auto_keep` / `.auto_replace` / `.failed`。
  `tr_args!` を使う 3 キーは `crates/i18n/tests/placeholders.rs` の `CALL_SITES` にも登録されている。
- 送信履歴の「待機」は `send.status.waiting` を共有しており、行の状態バッジ
  （`send_status_label`）でも使う。

## 仕様

### 圧縮キューのヘッダー

左から次の順に並べる。

1. タイトル「圧縮キュー」
2. 伸縮スペーサー
3. 「待機をすべて圧縮」（`waiting_job_count > 0` のときだけ）
4. 「失敗をすべて再試行」（`retryable_failed_count > 0` のときだけ）

- 件数・自動方針のバッジは生成しない。空の領域や代替チップも置かない。
- ヘッダーの高さ、余白、罫線、ボタンの体裁と条件は現状のまま。
- キューの行（待機行・失敗行・空表示）は変更しない。

### 送信履歴のヘッダー

左から次の順に並べる。

1. タイトル「送信履歴」
2. 「待機をすべて送信」（待機 0 件なら無効のまま表示）
3. 「履歴を消去」

- 待機件数のバッジは生成しない。
- 行（状態バッジ、写真名、ワールド、送信先、日時、試行、再試行・取消）は変更しない。

### 翻訳

- `compression.queue.active` / `.waiting` / `.auto_keep` / `.auto_replace` / `.failed` を
  `ja.yml` と `en.yml` の両方から削除する。
- `placeholders.rs` の `CALL_SITES` から `compression.queue.active` / `.failed` / `.waiting` を削除する。
- `send.status.waiting` は削除しない。

## 非対象

- ダッシュボードの統計カード、サイドバーのナビバッジ、通知、キュー行・履歴行の状態表示。
- 圧縮・送信の処理、ポーリング、DB スキーマ、設定項目。
- 新しいバッジ、ツールチップ、説明文、代替の件数表示。
- 圧縮設定など他画面の自動方針表示。

## 検証

- `cargo fmt --all -- --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace`
- i18n のカタログ・placeholder テストが通ること。
- 1080×700、サイドバー展開で、圧縮キュー（待機あり・失敗あり）と送信履歴（待機 0 件・あり）の
  ヘッダーが崩れず、ボタンだけが右に残ることを目視確認する。

## リスク

- バッジ削除で `tr!` / `tr_args!` の参照が残ると `every_tr_key_exists_in_the_default_catalog` が落ちる。
  呼び出し側とキーを同じ変更で消す。
- キーだけ残すと未使用キーになるため、`placeholders.rs` の登録も同時に消す。
- ヘッダーの `p` や件数フィールドは他画面でも使う。未使用警告が出た場合だけ、
  その変更内で参照を整理する（フィールド自体は削除しない）。
