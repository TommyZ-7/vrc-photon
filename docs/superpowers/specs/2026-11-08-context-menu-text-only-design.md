# 右クリックメニューのアイコン削除 設計 (#429)

## 目的

写真グリッド／検索結果グリッドの右クリックメニューから左アイコンを削除し、
テキストだけのメニューにする。項目の構成・順序・文言・有効条件・動作は
変更しない。

モック: `docs/ui-context-menu-text-only-mockup.html`

## 対象

- `crates/ui/src/app/context_menu.rs` の写真コンテキストメニュー
  （Issue 文面の `crates/ui/src/ui/actions.rs` はリファクタ前の参照。
  現在のメニュー構築は `app/context_menu.rs`）。
- ルートメニュー、圧縮サブメニューの両方。

## 対象外

- サイドバー、リボン、インスペクタ、カードなど、メニュー以外のアイコン。
- サブメニューを示す右端の `›`（`IconName::ChevronRight`）。
  これは項目アイコンではなく、サブメニューの存在を示す手掛かりとして残す。
- メニュー幅（既存の `min_w(px(252.))`）と開閉アニメーション。

## 方針

gpui-kit の `PopupMenu` は、メニュー内に左アイコンが1つでもあると
全項目にアイコン列の余白を確保する。逆に1つもなければ余白を確保せず、
ラベルはメニューの左パディングから始まる。この挙動をそのまま使う。

1. すべての `PopupMenuItem::icon(...)` を削除する。
2. `submenu_with_icon(Some(IconName::...), label, ...)` を
   `submenu(label, ...)` に置き換える。
3. 未使用になる `IconName` import を整理する。
4. 項目順、区切り線、文言、`disabled(...)`、`on_click`、`action` は
   一切変更しない。

これにより `PopupMenu::render` の `has_left_icon` が false になり、
全ラベルが同じ左位置から始まる。追加の余白調整やカスタムレイアウトは
入れない。

## リスクと確認

- アイコン付き項目が1つでも残ると、全項目にアイコン列の余白が戻る。
  ルート／サブメニューの全項目を確認する。
- 既存のメニュー関連テスト（有効条件、スナップショット、位置計算）が
  通ることを確認する。
- 実機で単一選択・複数選択・圧縮サブメニューの開閉を確認する。

## 受け入れ条件

- 単一選択・複数選択のどちらのメニューでも、全項目からアイコンが消える。
- 圧縮サブメニューの開閉と各項目の操作が従来どおり動作する。
- 既存のメニュー関連テストが通る。
