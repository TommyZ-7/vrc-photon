## #477: 連携・自動 左一覧の背景

### 現状

`App::integrations_list` は `v_flex` に幅と右側の区切り線だけを与えており、背景色を持たない。詳細ペインの各カードは `glass_panel`（`panel_card` + `line_soft` の境界 + 影）で描かれるため、左一覧だけウィンドウ背景が透けて見える。

### 変更

- 一覧全体を 1 枚のカードにする。`glass_panel(&self.palette)` を使い、角丸 17 px、内側 8 px の余白を置く。
- 外部幅は `INTEGRATIONS_LIST_WIDTH = 252.0` のまま変えない。内側の行幅だけが 8 px 分狭くなる。
- 現在の `pr(px(12.))` と `border_r_1()` は外す。カードの境界が詳細ペインとの区切りになる。
- スタック表示（狭い幅）でも同じカード面を使い、`pb(px(12.))` と `border_b_1()` は外す。
- 行の選択中 `accent_soft`、ホバー `panel_2`、状態ドット、文字サイズは変えない。
- 詳細ペインのカードとの間に `INTEGRATIONS_PANE_GAP = 16.0` の余白を保つ。

### 受け入れ条件

- 1280×820 と 1440×900 で、左一覧の背景が詳細カードと同じ `panel_card` に見える。
- 一覧の選択行・ホバー行が背景に埋もれず判別できる。
- 狭い幅でスタックしたときも、一覧と詳細の間に二重の境界線が出ない。
- 既存の `integrations` のサマリ文言・クリック動作に変化がない。

## #478: セッション折りたたみのアニメーション

### 現状の制約

`SessionRows::build` は折りたたみ済みセッションの写真行を最初から生成しない。そのため、行を消す瞬間に高さが即座に変わり、アニメーションの途中状態を表現できない。`v_virtual_list` は `item_sizes` の高さで行を配置するため、行の高さ自体を毎フレーム更新する必要がある。

### 状態

`PhotoBrowser` にセッション用のモーション状態を持たせる。

```rust
pub(crate) struct SessionCollapseMotions {
    motions: HashMap<i64, ToggleMotion>,
    epoch: u64,
}
```

- 値は `0.0 = 展開`、`1.0 = 折りたたみ`。
- `collapsed_sessions` はクリック直後に目標状態へ反転する（矢印・ツールチップは目標状態を表示）。
- モーションはセッション ID ごとに独立し、`ToggleMotion` の現在値から再目標化できる。
- `replace_index`、`clear_collapsed_sessions`、画面離脱でクリアする。
- reduce motion が有効なときはモーションを作らず、即時確定する。

### 行モデル

`SessionRows::build` に「アニメーション中のセッション集合」を渡す。

- 折りたたみ目標でも、アニメーション中は写真行を生成する。
- 見出し行の `collapsed` は目標状態（クリック直後に反転）を保持する。
- `heights_with_collapse(factors)` で、各セッションの写真行の高さに `1.0 - factor` を掛けた高さベクタを返す。行モデル自体は再構築しない。
- セッションが分断されている場合も、同じ `session_id` のすべての写真行範囲に同じ係数を適用する。
- モーションが終了した次の描画では、アニメーション集合から外れるため、折りたたみ済みなら写真行が消えたモデルに戻る。最終フレームの高さ 0 と消滅後の高さ 0 が一致するため、見た目の跳びはない。

### 描画

- `PhotoBrowser::session_layout(..., now)` が 1 回の `Instant::now()` で以下を返す。
  - アニメーション中のセッション集合を含む `Arc<SessionRows>`
  - アニメーション後の行高 `Vec<f32>`
  - フレーム駆動用の最大継続時間（元のモーション時間）と epoch
- `render_session_grid` はその行高を `v_virtual_list` の `item_sizes` に渡す。
- 写真行は `h(px(animated_height))` と `opacity(animated_height / base_height)` で描く。見出し行・日付ラベル行の高さは変えない。
- `GalleryView` に 0 サイズのフレーム駆動要素を 1 つ置き、`Animation::new(remaining + 50 ms)` と `.with_max_fps(effective_motion_fps(ui_max_fps, refresh_interval))` を設定する。アニメーションの animator は値を描画せず、`cx.notify(GalleryView)` による再描画だけを駆動する。50 ms の余白は、モーション終了後の 1 フレームで必ず行モデルを確定させるため。
- 複数セッションが同時に動くときは、元の継続時間が最大のものに合わせて 1 つの駆動要素でフレームを進める。途中で再クリックされたら epoch を進め、駆動要素を張り直す。

### スクロール

- クリック時は現行どおり、対象セッションの見出し行のオフセットへスクロールを合わせる。
- 見出し行は動かさず、その下の写真行だけが縮む / 伸びる。
- 折りたたみ中は、見出しの直後にある次の行が滑らかに上がる。
- 展開中は、見出しの下に写真行が 0 高さから現れ、下の行が押し下がる。

### キーボード・プログラムからの展開

- キーボード移動で隠れた写真へ選択が移った場合の自動展開（`reveal_photo_session`）は即時に行う。アニメーション中にスクロールすると選択位置が定まらないため。
- 画面離脱・索引再読込・折りたたみ状態のクリアも即時。

### アクセシビリティ

- 見出しのボタンの `aria-label` / ツールチップは従来どおり「折りたたむ」「展開する」を目標状態に合わせる。
- reduce motion が有効なときはフレームを要求しない。
- 写真行の高さが 0 の間はクリック・ホバー対象にならない（`overflow_hidden` と 0 高さ）。

### 受け入れ条件

- セッション見出しの ▾ で、写真行が 220 ms で滑らかに折りたたまれる。▸ で逆方向に展開する。
- 見出しの位置が動かず、下の行だけが追従する。
- アニメーション中に再度クリックしても、現在の途中値から跳ばずに反転する。
- 複数セッションを同時に操作できる。
- `ui_max_fps` を 30 / 60 / 120 に変えると、フレーム更新の上限が変わる。0 またはリフレッシュ同等では上限なし。
- reduce motion が有効なら即時切替になり、フレームが要求されない。
- キーボードで隠れた写真へ移動したときは即時展開され、選択写真が見える。
- 折りたたみ・展開の完了後にレイアウトの跳びや残像がない。
- 既存のスクロール、年レール、選択、右クリック、ダブルクリック、ページ読み込みに回帰がない。

## リスク

- **仮想リストの行高更新**: 毎フレーム `item_sizes` を作り直すため、行数が多いライブラリではコストが増える。行モデルはキャッシュし、高さベクタの更新だけに留める。30 / 60 / 120 fps で計測する。
- **スクロール位置**: 見出しを固定するため、アニメーション中にユーザーがスクロールした場合は年レールとの一時的なずれが出る可能性がある。見出し基準のスクロールを維持し、完了時に再計算する。
- **複数モーション**: 途中で別セッションを操作したときのフレーム駆動の取りこぼし。epoch と最大継続時間で 1 つの駆動要素に集約する。
- **reduce motion と既存設定**: `cx.reduce_motion()` の既存挙動に合わせ、モーションを作らない経路を必ず通す。
- **#477 の幅**: 内側 8 px でサマリの省略位置が少し変わる。狭い幅のスタック表示も含めて確認する。
