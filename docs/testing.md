# テスト方針

## 1. 自動テスト

### 実行

```bash
cargo test --workspace --locked
```

2026-11-11時点の例（CI の `test` ジョブの `test result` 行から更新。最新の件数はCIを正とする）:

- `vrc-photon-core`: 561 passed / 1 ignored
- `vrc-photon-daemon`: 306 passed / 1 ignored
- `vrc-photon-ipc`: 41 passed
- `vrc-photon-update`: 147 passed
- `vrc-photon-release-tool`: 9 passed
- `vrc-photon-signing`: 3 passed
- UI: 571 passed（GPUIを起動しない純粋ヘルパーとIPCブリッジの単体テスト）

件数は各クレートの lib 単体テスト（UI は bin）の passed / ignored。統合テストと
doc-test は含めない。`--list` で総数を確認する場合は
`cargo test -p <crate> --lib -- --list | grep -c ': test$'`
（UI は `cargo test -p vrc-photon-ui --bin vrc-photon -- --list`）を使う。

### ipcの主なテスト

- プロトコル型のJSON往復（リクエスト、イベント、バージョン）。
- 改行区切りフレーミング（複数メッセージ、EOF）。
- 一時エンドポイントでのリクエスト/レスポンス、購読イベント。
- プロトコルバージョン不一致。
- 生存中エンドポイントをunlinkしないこと、stale socketの置き換え（Unix）。

### coreの主なテスト

### updateの主なテスト

- マニフェストのスキーマ、バージョン、サイズ、SHA-256、URL、安全なファイル名、
  未知のプラットフォームキーの検証。
- `system_packages` の pacman / deb の受理、未知キー・format 不一致・拡張子
  不一致・HTTP URL・サイズ / ハッシュ不正の拒否、`system_packages` のない
  旧 manifest の受理、family に応じた asset 選択。
- minisignのprehashed署名検証、改ざん・別鍵・legacy署名の拒否、本番公開鍵の読み込み。
- AppImage / Windows current-user / per-machine / deb / pacman / 開発ビルドの判定と
  自動適用・自動確認の可否、`pkexec` / ヘルパー / policy の有無による
  システムパッケージ適用可否、`find_executable_in`。
- 署名付きフィードの確認、404の扱い、ローカルHTTPのポリシー、タイムアウト。
- ストリーミングダウンロードの署名・SHA-256・サイズ・キャンセル・部分ファイル削除。
- 適用ジョブの検証、システムパッケージ job の必須フィールド・staging パス・
  拡張子の検証、`ApplyKind::SystemPackage` の serde 往復、ヘルパーのコピーと
  ジョブ書き込み、AppImageの退避・復元。
- ヘルパーのプロセス終了待ち、健康マーカー、成功・起動失敗時のロールバック。
- システムパッケージの特権側: manifest 署名不正・バージョン不一致・
  ダウングレード・staging 外 / symlink・パッケージ名 / バージョン不一致の拒否、
  root 一時ファイルへのコピーと削除、`pacman -Qip` / `dpkg-deb -f` の引数、
  固定インストールコマンド（`pacman -U --noconfirm` / `dpkg -i`）、
  `LC_ALL=C` / `DEBIAN_FRONTEND=noninteractive`、DB ロック検出、
  `--apply` の root 実行ガード。

### release-toolの主なテスト

- AppImageとNSISからのマニフェスト生成、`.minisig` のbase64埋め込み。
- pacman / deb の `.pkg.tar.zst` / `.deb` を含む `system_packages` の生成。
- 欠落・重複・タグバージョンを含まないファイル名の拒否。
- テスト鍵での署名と、アプリと同じ `verify_file` 経路での検証。

### mcpの主なテスト

- ツール一覧とパラメータの丸め（`limit` 1〜200、`offset`、RFC 3339 の日時）。
- `search_photos` / `random_search_photos` のフィルタ転送と `seed` の再現性。
- `get_photo` / `get_photo_image` の成功・`photo_not_found` / `image_unavailable`。
- `list_worlds` / `library_stats` の往復。
- デーモン未接続時の `daemon_unavailable`。

### i18nの主なテスト

- `tr_args!` のプレースホルダが日本語・英語の両方に存在すること。
- 未知のロケールが日本語へフォールバックすること。

### daemonの主なテスト

- ログの不完全行を次回に回す。
- 最新ログファイルの選択。
- 写真 + ログのE2E（索引 → 紐付け → 外部削除でmissing）。
- 自動圧縮E2E（自動圧縮設定 → キュー → 圧縮 → derivative）。
- 同一写真の複数ジョブを1バッチで処理し、全て完了すること。
- `replace` 後の後続ジョブが派生ファイルではなく元画像を読むこと（寸法で検証）。
- 1ジョブ失敗時も同じ写真の他ジョブが完了すること。
- デコード失敗時にバッチ内の全ジョブが`failed`になること。
- 強制削除で残りのバッチジョブが`cancelled`になり、削除が進むこと。
- notify相当の増分索引。
- 写真フォルダが見つからないときに `scan` エラーを記録し、フォルダ作成後の `rescan` で消える。
- 失敗のあるルートスキャンでは、そのルートの写真をmissingにしない。
- 不正なログフォルダで `log` エラーを記録し、正しいフォルダと `relog` で消える。
- 失敗ジョブをDBで作り、再試行 → 圧縮 → 完了まで通す。
- `daemon_commands` の処理で設定を再読込し、新しいルートの監視を張り直す。
- `scan_root` が対象ルートだけを索引し、他ルートの写真をmissingにしないこと。
- 設定に無い実在ディレクトリの `scan_root` が索引されること。
- `scan_root` の新規写真が `auto_compress_backlog=false` でも自動圧縮に載ること。
- 起動時に保留中の `scan_root` が初回フルスキャンより先に処理され、取り込み写真だけが自動圧縮に載り、既存ルートのバックログは載らないこと。
- `ScanFinished` が `auto_enqueued` と対象ルートを運ぶこと。
- 同じ写真の自動圧縮 enqueue が重複しないこと。
- 自動圧縮 enqueue はプロファイルの有無に依存しないこと。
- 無変更の再スキャンで `library_revision` が上がらないこと。
- `run_once` が処理前にコマンドを消化する。
- ワールド名解決ワーカーが成功時に `worlds.name` と `photo_context` を更新し、次のリクエストを60秒後にすること。
- 無効時はワールド名解決ワーカーが `fetch` を呼ばず、再起動後は保存済みの次回リクエスト時刻まで待つこと。terminal 行を再取得しないこと。
- IPCサーバーのhello/status、`wake_commands` がDBを触らずにwakeすること、`set_paused` の状態変更とイベント、`shutdown` のrunning/wake。
- IPCの読み取り要求（`search_photos` / `random_search_photos` / `get_photo` / `list_worlds` / `library_stats`）と、ランダム抽選の `seed` 再現性・件数上限。
- `scan_photos` のScanStarted / ScanProgress / ScanFinished、`set_paused` のStatusChanged、`daemon_errors` 変更イベントの重複抑止。
- `Daemon::start_ipc` がstatusを返すこと。

### UIの主なテスト

GPUIのウィンドウは開かず、表示に使う純粋関数だけを検証する。

- revision / 件数の quiet デバウンスが連続変化を1回にまとめること。
- `ScanFinished` の画面別ガード（Photos の変更なしは再読込しない、Search は再検索、他は dirty のみ）。
- 通知モーダルのセクション優先順位（圧縮 → デーモン → 取り込み）。
- デーモン操作のラベルと再試行コマンドの対応。
- 取り込み結果の失敗数・部分移動数の集計と、再試行対象（`Failed` かつ `retryable`）の抽出。
- 取り込み結果の「自動圧縮 N」バッジが0件で非表示、1件以上で件数表示になること。
- `ScanFinished` の対象ルートが取り込み先と一致するときだけ自動圧縮件数を加算すること。
- 圧縮ジョブの再試行可否と `再試行 n/3` の表示（0回・2回・上限3回）。
- タイムスタンプの `MM/DD HH:MM` 変換と生文字列フォールバック。
- `daemon_liveness` がハートビートまたはIPC接続で稼働と判定すること。
- セッション行モデルの見出し・日付ラベル・折りたたみ・オフセット計算。
- 右クリックメニューの有効条件（クリップボード1枚・設定ON、Discord 1枚・連携ON、AI準備完了）とスナップショットの陳腐化。
- 背景読み取り接続の再利用とフォールバック。
- IPCブリッジの接続→イベント受信、デーモン不在時の切断通知。
- スキャン進捗ラベル/比率、IPC接続ラベル。
- 更新のバイト表示、最終確認ラベル、成功/ロールバック結果の文言、適用可否、
  インストール形式ラベルとパッケージコマンド。
- `SystemPackage` の `system_apply_available` による適用可否と、自動適用不可時の
  コマンド表示。`LastErrorCode` ごとの通知文言。健康確認失敗時に新バージョン側でも
  失敗通知が出ること。
- `should_use_systemd` と、systemd 管理デーモンの起動 / 更新後再起動の分岐。

## 2. 追加すべきテスト

優先度順:

1. `replace` ポリシー（OSゴミ箱はモック/一時ディレクトリで検証）
2. 圧縮ジョブの複数ワーカー同時取得
3. XMPの実ファイル（VRChatが出力したPNG）での検証
4. DST/タイムゾーン境界
5. 10万件の検索クエリ性能（`photo_index_text` のignoredベンチマークで一部実施済み）
6. UIのヘッドレス操作テスト（gpui-kit test-support）
7. AppImage/deb/pacmanのインストール後起動（実機/CIコンテナ）

## 3. 手動確認チェックリスト

リリース前・大きなUI変更後に実施する。

### 写真索引

- [ ] VRChat写真フォルダを指定して起動すると一覧に出る
- [ ] 新規PNGを追加すると自動で出る
- [ ] `compressed/` 内の生成物が写真として索引されない
- [ ] 外部で削除した写真が一覧から消える
- [ ] 同名・別パスの写真が別エントリになる
- [ ] 大量の写真を取り込んでも、取り込み中に Photos 画面が操作できる
- [ ] 取り込み完了後、取り込み先の新規写真だけが索引され、無変更の既存写真は再 upsert されない
- [ ] 取り込み中に revision が連続変化しても、全件再読込が繰り返されない

### 表示モード

- [ ] 写真画面で「時系列 / セッション」を切り替えられる
- [ ] セッション見出しにワールド名、滞在時刻、枚数、同席プレイヤーが出る
- [ ] セッションを折りたたみ、展開できる。索引再読込後も残っているセッションの状態が引き継がれる
- [ ] 未紐付け写真が時系列の位置のまま日付ラベル付きで出る
- [ ] モードを切り替えても先頭写真の位置が大きくずれない
- [ ] 再起動後も選択したモードが復元される

### 右クリックメニューとビューア

- [ ] 写真カードの右クリックと `Shift+F10` でメニューが開く
- [ ] 圧縮サブメニュー、Discord、AIタグ付け、タグ編集、パスをコピー、フォルダを開く、ゴミ箱が動く
- [ ] 複数選択時にクリップボード圧縮と Discord 送信が無効になり、理由が表示される
- [ ] スクロール、リサイズ、ウィンドウ非アクティブ化でメニューが閉じる
- [ ] ビューアで `+` / `-` / `0` とダブルクリックのズーム、ドラッグのパン、ミニマップが動く

### IPC

- [ ] UIとデーモンを起動するとダッシュボードが「IPC 接続中」になる
- [ ] 「再スキャン」でスキャン進捗が即時表示される
- [ ] 「監視を一時停止/再開」が状態とサイドバーに反映される
- [ ] 圧縮ジョブの開始・完了がポーリング待ちなしでキューに反映される
- [ ] 「デーモンを終了」でデーモンが終了し、UIは落ちずに「デーモン停止」になる
- [ ] デーモン停止中にUIを起動しても落ちず、再試行要求がDBに残る
- [ ] UIとデーモンのバージョンが違うとき、IPCエラーが出てもUIは操作を継続できる

### ログ・XMP

- [ ] ワールド参加後に撮った写真へワールド名が付く
- [ ] 入室中のプレイヤーが写真に付く
- [ ] 退出済みプレイヤーが付かない
- [ ] ログがない写真にXMPの撮影者/ワールドが付く
- [ ] プライベートワールドでID表示になる
- [ ] 24時間より前のログがない場合、未紐付けのままになる

### ワールド名解決

- [ ] 名前のないワールドの写真がある状態で設定の「ワールド名解決」をONにすると、60秒間隔で名前が付く（件数が多いと時間がかかる）
- [ ] OFFのままでは API リクエストが発生しない（プロキシ／パケットキャプチャで確認）
- [ ] 存在しないワールドIDは `wrld_...` 表示のまま
- [ ] デーモンを再起動しても、解決済みワールドを再取得せず、保存済みの次回リクエスト時刻まで待つ
- [ ] 429 の後は `Retry-After`（1〜3600秒に clamp、最低60秒）以上待つ
- [ ] DB とログに VRChat API 用の認証情報（Cookie・トークン・`Authorization`）がない（Discord Webhook URL は DB に保存される）
- [ ] `--once` ではネットワークリクエストが発生しない

### 圧縮

- [ ] 自動圧縮で元画像が残る（既定の `auto_compress_keep_original=true`）
- [ ] 自動圧縮の元画像設定をOFFにしても、手動圧縮ダイアログの初期値は「保持」のまま
- [ ] 手動 `keep` で別ファイルができる
- [ ] 手動 `replace` で元画像がゴミ箱へ移る
- [ ] 手動圧縮で指定フォルダ／プロファイル指定フォルダを選び、出力先が切り替わる
- [ ] 手動圧縮のクリップボード出力は1枚選択時だけ有効で、PNGがコピーされる
- [ ] 出力名衝突で連番になる
- [ ] 出力先に書き込めない場合、ジョブがfailedになり元画像が残る
- [ ] キューがデーモン再起動後も再開する
- [ ] プロファイルの ↑↓ 並び替えが再起動後も残る
- [ ] 複製が元の直後に入り、名前が重複しない
- [ ] 複製を編集しても元のプロファイルが変わらない
- [ ] 削除確認でキャンセルすると何も消えない
- [ ] 未完了ジョブがあるプロファイルは削除できない
- [ ] 最後の1件のプロファイルは削除できない
- [ ] 自動圧縮がプロファイルの並び替えの影響を受けずにキューへ入る
- [ ] 失敗ジョブに写真名・プロファイル名・失敗理由・`再試行 n/3` が出る
- [ ] 個別の「再試行」でジョブがキューに戻り、完了する
- [ ] 「失敗をすべて再試行」が上限到達ジョブを除外し、戻した件数を表示する
- [ ] 3回再試行したジョブ（`retry_count=3`）は再試行できず、上限メッセージが出る
- [ ] ライブラリで `Ctrl/Cmd+クリック` と `Shift+クリック` を使い、2件以上で選択バーが出る
- [ ] 検索タブでも同じ複数選択ができ、検索実行・クリアで選択が解除される
- [ ] 複数選択の「N件を圧縮」で、ダイアログの対象枚数とキュー追加件数が一致する

### エラー表示・再試行

- [ ] デモDBに失敗ジョブと `daemon_errors` の行を入れ、タイトルバーの通知ベルにドットが出る
- [ ] 通知モーダルの「ダッシュボードを開く」で対象画面へ移動する
- [ ] 有効なファイルと存在しないパスを同時に取り込み、成功分が処理され、失敗ファイルの元パスと理由が「取り込み結果」パネルに出る
- [ ] 「失敗分を再試行」が再試行可能な失敗だけを再実行する
- [ ] 移動取り込みで元ファイル削除を失敗させ、部分移動が警告として出る（取り込み済みに数え、再試行対象にしない）
- [ ] ダッシュボードの「処理エラー」カードに操作・メッセージ・詳細・検出回数・時刻が出る
- [ ] 「再試行」で `daemon_commands` にコマンドが入り、デーモンが処理してエラーが消える
- [ ] デーモン停止中に「再試行」を押すと、キューに残り起動後に実行される
- [ ] 写真フォルダを一時的に消してスキャンエラーを出し、戻して「再試行」で解消する
- [ ] 不正なログフォルダでログエラーを出し、正しいパスを保存して「再試行」で解消する
- [ ] 設定で写真フォルダ・ログフォルダ・取り込み先のいずれかを変更して保存すると再スキャンが要求され、デーモン再起動なしで監視に反映される

### ログ

- [ ] `logs/vrc-photon.log` と `logs/vrc-photon-daemon.log` が作成される
- [ ] 設定画面とダッシュボードの「ログ」カードに保存先と2ファイル名が出る
- [ ] 「ログフォルダを開く」でOSのファイラーが開く

## 5. CI

- PR: `test` ジョブ（fmt / clippy / test）。docs-onlyはfast-pass。
- `changes` ジョブで `scripts/check-docs-drift.sh` を実行し、IPCプロトコル・schema・サムネイル層数の記述をソースと照合する。
- PR（release-relevant paths）: Releaseワークフローで3形式をビルドし、
  Arch Linux コンテナで `.pkg.tar.zst` を生成する。
- Release ワークフローの検証: deb / pacman の polkit policy、systemd unit、
  `latest.json` の `system_packages` が pacman / deb の2件、
  `.pkg.tar.zst` の `LC_ALL=C pacman -Qip` による `Name` / `Version` /
  `Architecture` の一致。
- tag: 3形式と `.pkg.tar.zst` をビルドしGitHub Releaseへ添付。
- `main` の必須チェックは `test`。

## 6. テスト追加のルール

- バグ修正には再現テストを追加する。
- ログ解析は匿名化した実ログフィクスチャを使う。
- 画像テストは小さな生成PNGを使い、外部ファイルに依存しない。
- サムネイルやインポートのテストは一時ディレクトリを使い、ユーザーデータディレクトリを汚さない。
