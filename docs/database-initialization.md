# データベースの初期化と schema バージョン

## 概要

VRC PhotoN は SQLite の `user_version` でライブラリ DB の schema バージョンを管理する。現在のビルドが扱うのは **v19 のみ** で、新規 DB は v19 の統合 schema を 1 回のトランザクションで作成する。旧バージョンの DB をその場で移行する処理は持たない。

## 新規ライブラリ

`Db::open` は次の順で DB を開く。

1. `user_version == 0` かつユーザーテーブルが 1 つもない場合、`SCHEMA_LATEST` を `IMMEDIATE` トランザクションで実行し、`user_version = 19` にする。
2. 初期化は 1 トランザクションなので、途中で失敗した場合はテーブルが部分作成されない。
3. 複数プロセスが同時に新規 DB を開いても、書き込みロック取得後に `user_version` を再確認するため、二重初期化にはならない。

`schema_migrations` テーブルは使用しない。

## 既存ライブラリ

| `user_version` | 動作 |
|---|---|
| 19 | そのまま開く。ファイルは変更しない。 |
| 1〜18 | `CoreError::Invalid` を返して開かない。ファイルは変更しない。 |
| 20 以上 | このビルドより新しい schema としてエラーを返す。VRC PhotoN を更新する。 |
| 0（テーブルあり） | 不明な初期化状態としてエラーを返す。ファイルは変更しない。 |

v1〜v18 の DB を開いた場合、エラーメッセージに「このビルドでは移行できない」ことと、バックアップして新しいライブラリを作成する案内が含まれる。旧 DB は自動変更しないため、必要に応じて手動でバックアップしてから新しいライブラリを作成する。

読み取り専用接続 (`Db::open_read_only`) も v19 のみ受け付ける。v19 以外では書き込みを行わずにエラーを返す。

## 初期化 SQL の保守

`SCHEMA_LATEST` は `crates/core/src/db/schema.rs` にある。schema を変更するときは、この統合 SQL と `SCHEMA_VERSION` を同時に更新する。過去バージョン向けの `migrate_v*` は追加しない。
